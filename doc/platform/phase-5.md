# Phase 5: fixes from a security review

Branch `platform/5-review-fixes`, on top of phase 4. After phases 2 to 4 were written, the new server code was read by an independent reviewer looking for exploitable or data-corrupting faults. This phase fixes what was found. Each fix has a test.

## Found and fixed

| What could go wrong                                                                                                                                                                                                           | Fix                                                                                                                                                                                                                                                                                              |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **One device could freeze a school server.** Password hashing ran on the main thread, and a sign-in for an unknown username always ran it with no limit, so a loop of sign-in requests stopped the server answering the class | Hashing now runs off the main thread, two at a time, with a short queue; beyond it callers are told the server is busy. The school server also limits POST requests from one device (120 in 10 seconds, `POST_LIMIT`)                                                                            |
| **Anyone on the school network could lock the school admin out** by typing their username with five wrong passwords, again and again. The lock message also showed which usernames exist                                      | School sign-in tries are now counted for the username typed and the device it came from. Someone guessing on one phone locks only that phone, an unknown username is counted exactly like a real one, and the admin's own device is unaffected                                                   |
| **A burst of guesses sent at the same moment dodged the lockout**, because each read the count before any wrote it. On the console the same gap let one authenticator code be used by two sign-ins at once                    | The try is now counted in one database statement before the password is checked, and a code's 30-second step is claimed in one statement                                                                                                                                                         |
| **A suspended or expired school could still sign in and read its People list**, invite codes included, by calling the app's data addresses directly. Only pages and changes were blocked                                      | The school server now refuses the data addresses when the licence is closed, and the account calls check it themselves as well                                                                                                                                                                   |
| **An old check-in answer could be played back** by someone on the network path, cancelling a suspension and setting the licence clock back                                                                                    | Each check-in sends a random value that the control service signs into its answer; an answer for a different request, or older than the one already held, is refused. The school server will only talk to the control service over https (plain http is allowed to the same computer, for tests) |
| **A server whose clock was once set far ahead stayed locked for good** if it never went online                                                                                                                                | Installing a licence issued after the one it replaces resets the licence clock to that licence's issue time, once. Installing the same licence again does not. The way back: correct the clock, then install a newly issued licence                                                              |
| **A platform admin whose invite ran out, or who was disabled, could not be invited again**, although the notes said that was the recovery path                                                                                | Re-inviting reuses the account with its password and authenticator cleared                                                                                                                                                                                                                       |
| **A broken connection could crash the school server**, and abandoned downloads leaked open files                                                                                                                              | Files and pages are streamed with `pipeline`, which cleans up and contains errors                                                                                                                                                                                                                |
| The installer-only address for making the first school admin could be reached from the school network (it still needed the key)                                                                                               | It now also requires the request to come from the server itself, and compares the key in constant time                                                                                                                                                                                           |
| A new-password code lasted 30 days although it takes over an existing account                                                                                                                                                 | It lasts 24 hours                                                                                                                                                                                                                                                                                |
| The data folder and the database folder were readable by other users on the machine                                                                                                                                           | Both are private to the server's user                                                                                                                                                                                                                                                            |
| Expired sessions were never removed                                                                                                                                                                                           | They are removed at each sign-in                                                                                                                                                                                                                                                                 |
| The read-only notice was inserted with a pattern replace, so `$` in a school's name would be misread                                                                                                                          | It is inserted with a function                                                                                                                                                                                                                                                                   |

## Looked at and found sound

The reviewer also reported no fault in: the header boundary between the school server and the app (a browser cannot forge the licence standing, the device address or the internal secret); path handling in the file server; SQL (every query uses parameters); the console's permission check on every call; single use of invite, enrolment and new-password codes; the seat limit; licence signature checks and the refusal of older licences; and what is logged or returned.

## Still open

- **A platform admin can be locked out by someone who knows their email** and sends five wrong passwords, every 15 minutes. The console still counts tries for the account, because the device address it sees online can be forged. The authenticator code still protects the account. A second admin, or a database change, is the way out today.
- **The console has no request limit of its own.** Online it sits behind the host's protection only.
- **The seat limit is safe because a school server's database has one connection.** If a school server is ever moved to a full Postgres server, the approval statement needs a lock.
- **No dependency audit** was done.
- The limits already listed in [phase-3.md](phase-3.md) and [phase-4.md](phase-4.md) stand, in particular plain http on the school network and no protection against someone with root on the server.
